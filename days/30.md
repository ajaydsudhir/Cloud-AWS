# Day 30: Enable Internet Access for Private EC2 using NAT Instance

## Task
The Nautilus DevOps team is tasked with enabling internet access for an EC2 instance running in a private subnet. This instance should be able to upload a test file to a public S3 bucket once it can access the internet. To minimize costs, the team has decided to use a NAT Instance instead of a NAT Gateway.

The following components already exist in the environment:

1. A VPC named `nautilus-priv-vpc` and a private subnet named `nautilus-priv-subnet` have been created.

2. An EC2 instance named `nautilus-priv-ec2` is already running in the private subnet.

3. The EC2 instance is configured with a cron job that uploads a test file to the S3 bucket `nautilus-nat-431154928` every minute. Upload will only succeed once internet access is established.

Your task is to:
- Create a new public subnet named `nautilus-pub-subnet` in the existing VPC.
- Launch a NAT Instance in the public subnet using an Amazon Linux 2023 AMI and name it `nautilus-nat-instance`. Configure this instance to act as a NAT instance. Make sure to use a custom security group for this instance.

After the configuration, verify that the test file `nautilus-test.txt` appears in the S3 bucket `nautilus-nat-431154928`. This indicates successful internet access from the private EC2 instance via the NAT Instance.

**Note:** `iptables` is not installed by default on Amazon Linux 2023. You will need to install and enable it before configuring NAT setup.

## Solution
1. Login to the AWS Management Console using the provided credentials and navigate to the VPC service.
2. Create a new public subnet named `nautilus-pub-subnet` in the existing VPC `nautilus-priv-vpc` with the IPv4 CIDR block `10.1.2.0/24`.
3. Edit the subnet settings to enable auto-assign public IPv4 address for the new public subnet.
4. Create a Internet Gateway named `pub-IGW` and attach it to the VPC `nautilus-priv-vpc`.
5. Edit the route table associated with the public subnet and add a route to the Internet Gateway for `0.0.0.0/0`.
6. Associate the public subnet with the route table that has the Internet Gateway route.
7. Create a EC2 instance with the following specifications:
    - Name: `nautilus-nat-instance`
    - AMI: Amazon Linux 2 (from the AWS Marketplace)
    - Instance Type: t3.micro
    - Key Pair (login): Proceed without a key pair 
    - Network Settingss:
        - VPC: `nautilus-priv-vpc`
        - Subnet: `nautilus-pub-subnet`
        - Security Group: 'pub-SG`
        - Inbound Secutiry Group Rules: Allow SSH (port 22) and allow all traffic from the private VPC (`10.1.0.0/16`).
8. Under `Change Source/Destination Check` settings, stop the source/destination check for the NAT instance.
9. Connect to the NAT instance and run the following commands:
```bash
sudo yum install -y iptables-services
sudo sysctl -w net.ipv4.ip_forward=1
echo "net.ipv4.ip_forward = 1" | sudo tee -a /etc/sysctl.conf
sudo /sbin/iptables -t nat -A POSTROUTING -o ech0 -j MASQUERADE
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
sudo iptables -A FORWARD -i eth0 -m state --state RELATED,ESTABLISHED -j ACCEPT
sudo iptables -A FORWARD -o eth0 -j ACCEPT
sudo service iptables save
sudo systemctl enable iptables
sudo systemctl start iptables
sudo iptables -t nat -L -n -v
sudo systemctl status iptables
```
10. Edit the route table associated with the private subnet and add a route to the NAT instance for `0.0.0.0/0`.
