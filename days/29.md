# Day 29: Establishing Secure Communication Between Public and Private VPCs via VPC Peering

## Task

## Solution
1. Log in to the AWS Management Console using the provided credentials and navigate to the EC2 service in the `us-east-1` region.
2. Ensure that the existing EC2 instances and VPCs are present as described in the task.
3. Create a VPC Peering Connection:
   - Go to the VPC service in the AWS Management Console.
   - Click on "Peering Connections" in the left-hand menu.
   - Click on "Create Peering Connection."
   - Name: `devops-vpc-peering`
   - Requester VPC: Default VPC
   - Accepter VPC: `devops-private-vpc`
4. Update Route Tables:
   - For the private VPC's route table, add a route to the public VPC's CIDR (e.g., `172.31.0.0/16`) with the target being the peering connection.
   - For the public VPC's route table, add a route to the private VPC's CIDR (`10.1.0.0/16`) with the target being the peering connection.
5. Update Security Groups:
   - Modify the security group of the private EC2 instance to allow inbound ICMP traffic (for ping) from the public VPC's CIDR.
   - Ensure that the public EC2 instance's security group allows outbound traffic to the private VPC's CIDR.
6. Test the Connection:
   - SSH into the public EC2 instance (`devops-public-ec2`) using the provided credentials.
   - From the public EC2 instance, attempt to ping the private EC2 instance (`devops-private-ec2`) using its private IP address.
   - If the ping is successful, the VPC peering connection is working correctly, and secure communication between the public and private VPCs has been established.

## Notes
- `Peering Connections` are a way to connect two VPCs privately using AWS's internal network. This allows instances in different VPCs to communicate with each other as if they were within the same network.
