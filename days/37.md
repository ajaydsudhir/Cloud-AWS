# Day 37: Managing EC2 Access with S3 Role-based Permissions

## Task
The Nautilus DevOps team needs to set up an application on an EC2 instance to interact with an S3 bucket for storing and retrieving data. To achieve this, the team must create a private S3 bucket, set appropriate IAM policies and roles, and test the application functionality.

**Task:**

1. **EC2 Instance Setup:**
   - An instance named `xfusion-ec2` already exists.
   - The instance requires access to an S3 bucket.

2. **Setup SSH Keys:**
   -  Create new SSH key pair (id_rsa and id_rsa.pub) on the `aws-client` host and add the public key to the `root` user's authorized keys on the EC2 instance.

3. **Create a Private S3 Bucket:**
   - Name the bucket `xfusion-s3-907301661335`.
   - Ensure the bucket is private.

4. **Create an IAM Policy and Role:**
   - Create an IAM policy allowing `s3:PutObject`, `s3:ListBucket` and `s3:GetObject` access to `xfusion-s3-907301661335`.
   - Create an IAM role named `xfusion-role`.
   - Attach the policy to the IAM role.
   - Attach this role to the `xfusion-ec2` instance.

5. **Test the Access:**
   - SSH into the EC2 instance and try to upload a file to `xfusion-s3-907301661335` bucket using following command:

   ```aws s3 cp <your-file> s3://xfusion-s3-907301661335/```

   - Now run following command to list the upload file:

   ```aws s3 ls s3://xfusion-s3-907301661335/```

## Solution
1. Login to the AWS Management Console using the provided credentials and navigate to the `us-east-1` region.
2. Navigate to the security group associated with the `xfusion-ec2` instance.
3. Edit the inbound rules to allow SSH access (port 22) from Everywhere for IPv4.
4. On the AWS Client host, generate a new SSH key pair using `ssh-keygen` and display the public key using `cat /root/.ssh/id_rsa.pub`.
5. Connect to the `xfusion-ec2` instance and run `sudo -i` to switch to the root user. 
6. Add the public key to the `.ssh/authorized_keys` file of the root user on the EC2 instance.
7. On the AWS Client host, SSH into the `xfusion-ec2` instance using the the public IPv4 address.
8. Navigate to "S3" service in the AWS Management Console and create a new bucket named `xfusion-s3-907301661335`. 
9. Navigate to "IAM" service and create a new policy with the following JSON named `xfusion-s3-access-policy`:
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:PutObject",
                "s3:ListBucket",
                "s3:GetObject"
            ],
            "Resource": [
                "arn:aws:s3:::xfusion-s3-907301661335",
                "arn:aws:s3:::xfusion-s3-907301661335/*"
            ]
        }
    ]
}
```
10. Create a new IAM role named `xfusion-role` and attach the newly created policy and the `xfusion-ec2` instance to it.
11. Run the following commands on the AWS Client:
```bash
aws s3 ls s3://xfusion-s3-907301661335/
ls
touch hello.txt
aws s3 cp hello.txt s3://xfusion-s3-907301661335/
aws s3 ls s3://xfusion-s3-907301661335/
```
