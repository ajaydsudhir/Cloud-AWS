# Day 35: Deploying and Managing Applications on AWS

## Task
The Nautilus DevOps team needs a new private RDS instance for their application. They need to set up a MySQL database and ensure that their existing EC2 instance can connect to it. This will help in managing their database needs efficiently and securely.

1. **Task Details:**
    1. Create a private RDS instance named `devops-rds` using a `sandbox` template.
    2. The engine type must be `MySQL v8.4.5`, and it must be a `db.t3.micro` type instance.
    3. The master username must be `devops_admin` with an appropriate password.
    4. The RDS storage type must be `gp2`, and the storage size must be `5GiB`.
    5. Create a database named `devops_db`.
    6. Keep the rest of the configurations as `default`. Ensure the instance is in `available` state.
    7. Adjust the security groups so that the `devops-ec2` instance can connect to the RDS on `port 3306` and also open port `80` for the instance.

2. An EC2 instance named `devops-ec2` exists. Connect to this instance from the AWS console. Create an SSH key (`/root/.ssh/id_rsa`) on the `aws-client` host if it doesn't already exist. Add the public key to the authorized keys of the `root` user on the EC2 instance for password-less SSH access.

3. There is a file named `index.php` under the `/root` directory on the `aws-client` host. Copy this file to the `devops-ec2` instance under the `/var/www/html/` directory. Make the appropriate changes in the file to connect to the RDS.

## Solution
1. Login to the AWS console using the provided credentials and navigate to the RDS service.
2. Click on "Create database" and select the following options:
   - Engine type: `MySQL`
   - Engine version: `8.4.5`
   - Database creation method: `Full configuration`
   - Template: `Free tier`
   - DB Instance Identifier: `devops-rds`
   - Instance Configuration: `db.t3.micro`
   - Storage Configuration: `General Purpose SSD (gp2)` with `5 GiB` allocated storage
   - Additional storage configuration: Keep the default settings
   - VPC Security Group: Create a new security group.
   - Additional configuration: Create a database named `devops_db`
3. Review the configuration and click "Create database" to provision the RDS instance.
4. Create a new security group for the RDS instance that allows inbound traffic on port `3306` from the `devops-ec2` instance's security group with "SSH" and "HTTP" access enabled.
5. Navigate to the EC2 service and select the `devops-ec2` instance to connect to the created security group.
6. For the security group connected to the database, add an inbound rule to allow traffic from the security group of the `devops-ec2` instance.
7. On the `aws-client` host, check if the SSH key exists at `/root/.ssh/id_rsa`. If not, generate a new SSH key pair using `ssh-keygen`.
8. Connect to the `devops-ec2` instance and add the public key to the `~/.ssh/authorized_keys` file for password-less SSH access.
9. On the `aws-client`, SSH into the `devops-ec2` instance and copy the `index.php` file from `/root` to `/var/www/html/` using the command:
    ```bash
    scp /root/index.php ec2-user@<devops-ec2-public-ip>:/var/www/html/
    ```
10. Also remove the default `index.html` file from `/var/www/html/` to avoid conflicts.
11. Update the following in the `index.php` file:
```php
<?php
$dbname = 'devops_db';
$dbuser = 'devops_admin';
$dbpass = 'devops_password';
$dbhost = 'devops-rds.cluster-xxxxxxxxxxxxx.us-east-1.rds.amazonaws.com';
```
12. Save the changes and access the `devops-ec2` instance using its public IP in a web browser. You should see the message `Connected successfully` if everything is configured correctly.
